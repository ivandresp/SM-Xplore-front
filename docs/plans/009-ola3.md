## Regla de ramas

Front: `git checkout -b <rama> develop`, cierre con `npm run typecheck && npm run lint && npm test &&
npm run build` y `git checkout develop && git merge --ff-only <rama>`, después `git push origin develop`.
Backend: rama + push + PR (develop protegido). Un commit por bloque, Conventional Commits en español
sin tildes. Rama local `develop`, nunca rebase contra `origin/develop`.

### Bloque 2 — Front: contratos y datos (`feat/catalogo-filtros-datos`)

### Bloque 3 — FilterBar y estado en la URL (`feat/catalogo-filtros-ui`)

Tocar mtime de los CSS Modules al editar (Vite cachea la transformación).
Puerta: typecheck + lint + test.

### Bloque 4 — Buscador global (`feat/busqueda-global`)

Puerta: typecheck + lint + test.

## Riesgos asumidos

- Docker caído al arrancar: los tests de Testcontainers se marcan `skipped`; no se declara verde sin
  levantar el stack y volver a correr `ApplicationContextTest`.
- `status` en ms-03 es un enum de Spring: valor inválido devuelve 400 de conversión, no RFC 7807 con
  `code` (ms-03 no emite `code`).
- Los eventos usan `managerId`, no `guideId`: el parámetro se llama por lo que el dominio tiene.
