## Bloques

### B1 — Duplicados + caché (cerrado)

- **Cambio:** `src/services/cache.ts` (TTL 30 s, dedupe en vuelo, generación, tope 200) integrado
  en `httpClient` para GET/HEAD; clave con huella del token; mutaciones invalidan salvo
  `POST /interactions/view/**`; `saveToken`/`clearToken` vacían. `src/test/setup.ts` limpia entre tests.
- **Resultado:** montar 8/8/8/6/8 → **4/4/4/3/4**; volver 6/6/6/4/6 → **0**; `/app` admin 3 → **0**;
  build de producción, volver 0. Medidor reproducible: `node scripts/measure-requests.mjs`.
- **Decisión de contrato:** el gateway manda `Cache-Control: no-store` en toda respuesta. Esta caché
  es estado de aplicación (por pestaña, ligada al token, se vacía al cambiar de sesión), no una caché
  HTTP, así que **no lo obedece a propósito**. Si el equipo quiere semántica HTTP estricta, se quita
  ese header en los GET públicos desde backend.
- **Auditoría:** independiente y adversario, ambos **PASA CON RESERVAS** sobre `41c3237`; `3b76afb`
  cierra sus reservas bajas con test (huella del token, aborto previo, `AbortSignal` sin dedupe,
  regex anclada, rejuvenecimiento). Ese último commit no tiene firma nueva: así consta.
- **No probado:** Safari/Firefox, dos cuentas reales en navegador (sí test determinista), 403/429/500
  reales en `/app`, build de producción «antes».

### B5 — Recomendaciones: latencia, error, filtros y preferencias (siguiente)

- **Diagnóstico ya hecho:** caliente 15 ms; frío 0,74 s; 6,5 s solo en arranque con locks de Neo4j.
  El error genérico no se reproduce con el backend actual; el defecto real es que se descarta el
  `cause` y el mensaje apunta a una consola que no tiene nada.
- **Cambio:** registrar el error real (código/estado/campo) sin mostrar `detail`; ajustar el schema
  con el payload real delante; preferencias editables en el perfil; filtro/paginado explícito o
  «ver más» con el contrato real de ms-05 (`limit`).
- **Aceptación:** p95 < 1,5 s caliente y < 2,5 s frío, 5 muestras; renderiza con 0, 1 y muchas
  preferencias; test con el payload que rompía; en pantalla se ve por qué se filtró y cuántos hay.
- **Riesgo:** maquillar la latencia con un spinner. Se mide antes/después con `curl` y marca de
  tiempo en el navegador.
- **Skills:** `systematic-debugging`, `vercel-react-best-practices`, `api-designer` si cambia el endpoint.
